# 服务端功能说明

服务端**没有**给用户点的页面。它是一直开着的程序：用户端和管理端把「登录、浏览装备、加租物车、下单、付款、取货核销、归还、续租、审核商户」这些请求发给它，它检查是否允许，把结果存进 MySQL，需要时再去问微信、支付宝、短信、地图这些外面的服务。

可以把它理解成**总台**。两个前台说的话，都由总台记账，并在需要时给外面的公司打电话。

代码在 **`luyingzulin_server`**。启动类是 **`com.sqx.SqxApplication`**。启动成功时，窗口里打印「**露营租赁项目启动成功...**」。

本机开发时，请把 `application.yml` 里的环境设为 **`dev`**，数据库配置在 **`application-dev.yml`**，库名是 **`luyingzulin`**，和 **`db/lyzl.sql`** 一致。

端口是 **9188**。所有接口都在 **`/sqx_fast`** 下面。接口清单在：

http://127.0.0.1:9188/sqx_fast/doc.html

这个页面给开发时查看接口用。管理后台是另一个网站，用户手机页面也是另一个网站。

租赁商品、购物车、订单、取还货、押金、商户、钱包、优惠券，以及管理员、菜单、系统配置，都在 MySQL 库 **`luyingzulin`** 里。完整脚本是 **`luyingzulin_server/db/lyzl.sql`**。

当前开源配置下，**Redis 不是启动必需项**（`sqx.redis.open: false`）。若你在配置里打开了 Redis 相关能力，则需要本机 Redis 可用。

下面先说它为两个前台做哪些事，再说它会主动连接哪些外面的服务。

---

## 它为露营租赁用户（C 端）做的事

这些都是用户在手机里点一下之后，由服务端完成的：

- **注册和登录**：检查手机号和短信验证码，或检查密码。通过后发给用户一张登录凭证（JWT）。之后每个请求都要带这张凭证，否则视为没登录。微信小程序/H5 还可走微信授权（需在系统配置里开通）。
- **找回密码**：再次核对短信，然后保存新密码。
- **首页与分类**：返回当前城市可用的轮播、快捷入口（领券中心、租赁指南等）、按「整日租 / 小时租 / 过夜租 / 套餐」筛选的装备列表。
- **装备详情**：返回商品图、视频、规格、配件套餐、日/小时/过夜价格、押金、库存与可租状态。
- **租物车**：登录用户把装备加入租物车，选择租赁类型、取还时间、规格和套餐，服务端保存 **`rent_cart`** 记录并算预览价。
- **确认订单**：汇总租物车或立即预订的商品，选择**门店自提**或**同城送达**、取货门店/地址、优惠券，计算租金、押金、应付总额。
- **支付**：按用户选择的余额、微信或支付宝收款。支付结果以余额扣款成功，或微信、支付宝的异步通知为准。付成功后订单进入待取货等后续状态。
- **取货与核销**：生成取货码或核销记录。商户/门店扫码或后台确认后，订单进入「使用中（租赁中）」。
- **使用中与归还**：记录租期、续租申请、归还申请。到期或用户发起归还后进入待验收、待退押金等流程。
- **续租**：在租期内延长租期，重新计算增量租金。
- **押金**：用户押金账户与订单押金冻结/解冻/退还，和管理端「押金管理」联动。
- **优惠券**：判断能否领取、是否达到使用门槛，下单时抵扣，并记下流水。
- **钱包**：余额、充值入账、提现申请、资金明细。提现只生成待审核记录，不会自动打款到微信/支付宝。
- **会员 VIP**：会员套餐与权益展示（若后台已配置）。
- **邀请分销**：记录邀请关系、佣金汇总，供「推广中心」「我的团队」展示。比例读系统配置。
- **收藏**：用户收藏的装备列表。
- **消息**：系统通知、订单状态变更消息，写入 **`messages`** 表。
- **IM 咨询**：用户与商户、用户与平台客服的会话与消息（HTTP 接口为主，会话存库）。
- **商户侧（同一用户端 App）**：入驻申请、商品与库存、订单处理、取货核销、归还验收、经营钱包、员工账号等，由 **`/app/merchant/**`** 等接口提供。
- **帮助、协议、关于我们**：把后台写好的文章和协议正文发给用户端。
- **意见反馈**：保存用户提交的内容，供管理端「用户反馈」处理。

## 它为管理端做的事

- 工作人员登录，并按角色限制能看的菜单。登录验证码由服务端生成（验证码图片接口）。
- 提供**数据统计**：今日订单、成交额、租赁中订单、待验收、待审商户、待处理提现、C 端用户数、订单趋势等。
- **租赁业务**：分类、商品（含规格/套餐/图片/视频）、库存、定价规则、订单列表与详情、验收记录。
- **商户**：入驻审核、商户列表、保证金及退还审核。
- **运营**：轮播与首页配置、优惠券模板、用户钱包与提现、分销佣金、站内消息、平台客服会话、邀请海报配置等。
- **用户**：C 端用户列表、押金与钱包流水（从用户维度查看）。
- **系统**：管理员、角色、菜单、权限、字典、操作日志、系统配置（支付、短信、地图、文件存储、协议正文等）。

## 对接了哪些外面的服务

下面每一项都是服务端**真的会向外发送请求**的。密钥没填时，它不会假装成功，用户端会看到失败提示。

### 短信

验证码登录、注册、找回密码，都由服务端发短信。

可以切换多家，在管理端「系统配置」的短信配置里选：

- 腾讯云短信：https://cloud.tencent.com/product/sms
- 阿里云短信：https://www.aliyun.com/product/sms
- 短信宝：https://www.smsbao.com/

短信签名和模板要在对方网站申请，并和「短信模板」里的内容对应。只把程序跑起来，不会自动拥有短信额度。

### 微信支付

用户选择微信支付时，服务端用商户号和密钥向微信支付下单，并把拉起支付需要的信息交回手机。支付完成后，微信访问服务端的通知地址，服务端核对之后，再把订单或充值改成已支付。退款时同样用这套密钥向微信发起退款。

还需要微信公众平台上的小程序或公众号 AppId：https://mp.weixin.qq.com/ 。商户平台在 https://pay.weixin.qq.com/ 。

### 支付宝

和微信同一类流程：下单、拉起支付宝、等待支付宝通知，以及退款。需要支付宝开放平台的应用编号和密钥：https://open.alipay.com/ 。

### 图片与视频存储

用户和管理端上传的图片、视频（商品封面、详情图、轮播、头像等）由服务端接收，然后按「系统配置」里选中的方式保存：

- **本机硬盘**
- **阿里云 OSS**：https://www.aliyun.com/product/oss

同一次上传只走当前选中的那一种。选了阿里云但密钥不齐时，上传接口会失败。选本机硬盘时，文件留在服务器磁盘上，不需要阿里云账号。

### 腾讯地图

用户端选择城市、门店位置、距离展示时，会使用腾讯位置服务的 Key。申请地址：https://lbs.qq.com/ 。Key 填在管理端地图配置，用户端 `manifest.json` 里也有一份给 H5 地图用的 Key。两处都空着时，定位和地图能力会失败，手动选城市和地址仍可以提交订单。

### 在线客服与 IM

平台客服、用户与商户咨询的消息存在自己的数据库里，通过接口拉取和发送。管理端「官方客服会话」查看的是平台侧会话；商户在用户端「用户咨询」里回复。这条通道不经过微信聊天。

---

## 这些留在自己的数据库里

- **余额支付**：只改数据库里的钱包数字。
- **订单状态与租期**：支付渠道没配好时，微信和支付宝付不了；余额足够时可以走余额。
- **提现**：只保存收款账号和金额，等管理端审核。没有在这一步自动打款。
- **商品、库存、订单、邀请关系、积分和优惠券**：都在自己的数据库里。
- **站内消息与 IM 会话**：自己的服务器保存和转发。
- **操作日志、权限、角色**：只约束管理端工作人员。

---

## 两个前台怎样和它配合

用户端和管理端都不直接「自己保存订单」。它们把请求发给服务端，服务端再决定要不要去问微信、短信或图床。

所以：

- **服务端没启动**时，两个网站都能打开界面，但登录、列表、付款都会失败。
- 外面的密钥只配在服务端能读到的「**系统配置**」里。只在用户端页面上改文字，不会变成已经开通了微信支付。
- 管理端改完商品价格、首页轮播、优惠券并保存后，用户端**下次打开**才会看到新内容。
- 本机开发请用 **`dev`** 环境和 **`luyingzulin`** 库，不要用默认 **`prod`** 里的远程库，否则你改的数据不在本机 MySQL 里。
